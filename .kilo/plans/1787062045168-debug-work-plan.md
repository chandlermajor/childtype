# childtype Debug 工作计划

## 项目概况

childtype 是一款面向 8-12 岁儿童的浏览器打字练习扩展，已完成基础框架搭建。TypeScript 类型检查通过，webpack 构建正常（Firefox MV2 + Chrome MV3 双端构建成功）。

---

## 已排查的已确认问题

### 问题 1：`manifest.json` 根目录文件缺失且冗余

- `manifest.json`（根目录）存在且内容与 Chrome manifest 完全一致（MV3），但 `webpack.config.ts` 在构建 Firefox 时复制的是 `src/browser-firefox/manifest.json`（MV2）。根目录的 `manifest.json` 不会被构建流程使用，是残留文件，且与 Chrome manifest 重复。
- 根目录 `manifest.json` 缺少 `browser_action`（Firefox MV2 必需字段），如果手动加载为无打包扩展会缺少此字段导致 Firefox 无法加载。
- **建议**：删除根目录 `manifest.json`，避免混淆。

### 问题 2：`progressStore` 使用旧版回调 API 而非 Promise API

`src/shared/store/progress.ts` 第 9 行通过 `(typeof chrome !== 'undefined' ? chrome : browser).storage.local` 获取存储对象，但后续调用（第 14 行 `storage.get`、第 23 行 `storage.set`）使用的是 Firefox MV2 时代的回调风格 API（`storage.get(key, callback)`、`storage.set(obj, callback)`）。

而 `progress.ts` 第 41 行通过 `await import` 引入的 `utils` 和 `constants` 模块使用 ES module 风格。虽然当前代码能工作（因为 `get` 和 `set` 回调形式在两种浏览器中都兼容），但这是一个不一致之处：
- Chrome MV3 的 `chrome.storage.local.get()` 同时支持 Promise 和回调形式（兼容层）
- Firefox 的 `browser.storage.local.get()` 返回 Promise

**建议**：统一为 Promise 形式，移除 `new Promise` 包装，直接使用 `storage.get('childtype_progress')` 和 `storage.set({ childtype_progress: progress })`。

### 问题 3：`app.ts` 中 `timedWpmInterval` 在 `startTimedChallenge` 中未正确清理

`app.ts` 第 408 行 `startTimedChallenge` 中创建 `timedWpmInterval`，但在 `handleTimedResult` 中清理时使用了 `timedWpmInterval`，而 `timedWpmInterval` 的声明在第 449 行（函数定义之后），这本身在 JS 中不会报错（hoisting），但变量在使用前未初始化（初始值 `null`）。如果用户快速切换模式，`timedWpmInterval` 可能未正确清理上一个间隔。

更关键的是：`startTimedChallenge` 中的 `timedWpmInterval` 没有在 `handleTimedResult` 中清理（第 444 行只清理了 `timedInterval`，没有清理 `timedWpmInterval`），这会导致 WPM 实时显示循环持续运行，即使挑战已结束。

**建议**：在 `handleTimedResult` 中增加 `if (timedWpmInterval) { clearInterval(timedWpmInterval); timedWpmInterval = null; }`。

### 问题 4：`app.ts` 中 `timedInterval` 声明顺序问题

`app.ts` 第 448 行 `let timedInterval: number | null = null;` 在 `startTimedChallenge`（第 370 行）和 `handleTimedResult`（第 451 行）之后声明。虽然 JS hoisting 不会导致运行时错误，但 `startTimedChallenge` 第 375 行检查 `if (timedInterval)` 时，`timedInterval` 已被声明为 `null`（hoisting），逻辑正确。这不是 bug，但属于代码可读性问题。

**建议**：将 `let timedInterval` 和 `let timedWpmInterval` 声明移至文件顶部，与其他 let 变量放在一起。

### 问题 5：`app.ts` 中 `handleTimedResult` 缺少倒计时中断

`app.ts` 第 432-445 行的倒计时逻辑中，当 `remaining <= 0` 时清理了 `timedInterval` 但不触发 `onResult`。如果用户打字未完成但倒计时结束，`onResult` 不会被调用，结果不会被保存。

**建议**：在 `remaining <= 0` 时，如果 `typingArea` 存在且未完成，手动触发结果计算和保存。

### 问题 6：`app.ts` 中 `showTimedResultModal` 的重试按钮逻辑错误

`app.ts` 第 507-515 行：点击"再来一次"时调用 `startLesson(currentLesson)` 而非 `startTimedChallenge(seconds)`。如果用户正在计时挑战模式，点击重试会切换到 lesson 模式，丢失当前计时挑战上下文。

**建议**：需要记录当前计时时长，重试时重新调用 `startTimedChallenge(seconds)`。

### 问题 7：`app.ts` 中 `startLesson` 和 `startFreePractice` 销毁键盘组件

`app.ts` 第 168 行和 334 行在 `startLesson` 和 `startFreePractice` 中都销毁了 `keyboard` 实例，但 `startTimedChallenge` 第 391 行也销毁了 `keyboard`。三个模式共用一个全局 `keyboard` 实例，频繁创建/销毁会导致 AudioContext 的初始化开销，且在页面切换时可能产生状态不一致。

**建议**：考虑复用 keyboard 实例，通过 `flashKey(null)` + `updateHighlight(null)` 重置状态，而非完全销毁重建。

### 问题 8：`progress.ts` 中 `saveResult` 没有错误处理

`progress.ts` 第 31-68 行 `saveResult` 中有多次 `await` 调用（`getProgress`、`saveProgress`），以及 `import` 调用。任何一步失败（如 storage 写入失败、导入失败）都会导致整个流程中断，但没有任何 try/catch。

**建议**：添加 try/catch 包裹整个 saveResult 函数体，记录错误日志。

### 问题 9：`utils.ts` 中 `calculateStars` 逻辑缺陷

`utils.ts` 第 21-26 行：

```
if (accuracy < 60) return 1;
if (accuracy >= 90 && wpm >= 30) return 2;
if (accuracy >= 95 && wpm >= 50) return 3;
return 2;
```

当 `accuracy >= 60` 但 `accuracy < 90` 时，或 `accuracy >= 90` 但 `wpm < 30` 时，都会 fallback 返回 2。但逻辑上 60-89% 准确率应该给 1 或 2 颗星，当前代码统一返回 2 星，意味着准确率 60% 也能获得 2 星，门槛过低。

**建议**：根据 PROJECT.md 中的"星星评级"设计，重新审视阈值设置。

### 问题 10：`app.ts` 中 `renderStats` 未保存设置变更

`app.ts` 第 579-622 行 `initSettings` 中，字体大小、主题、音效的变更只更新了本地 `currentProgress.preferences`，但没有调用 `progressStore.save` 持久化。用户刷新页面后设置会恢复默认值。

**建议**：在每个设置变更的事件处理函数中增加 `progressStore.save(currentProgress)` 调用。

### 问题 11：`app.ts` 中 `currentMode` 值映射错误

`app.ts` 第 55 行 `currentMode = btnId.replace('btn-', '').replace('settings', 'free');` — 当点击"设置"按钮（`btn-settings`）时，`btnId` 变为 `settings`，经过 replace 后变为 `free`。但第 56-58 行的 `if (btnId === 'btn-settings')` 检查在 replace 之后，所以 `currentMode` 会被错误地设为 `'free'` 而非 `'settings'`。

虽然这不影响页面切换（CSS 类名控制），但如果后续代码依赖 `currentMode` 值会有问题。

**建议**：检查 `currentMode` 的使用位置，确保值正确。

### 问题 12：`app.ts` 中 `initLessonSection` 自动开始第一课

`app.ts` 第 104 行 `renderLessonsForLevel(1, selector)` 在初始化时自动开始 Level 1 第一课。但 `renderLessonsForLevel` 内部（第 157 行）也调用了 `startLesson(lessons[0])`，意味着页面加载后用户还没选择就会开始练习，可能不是期望行为。

**建议**：考虑在初始化时只显示课程列表，等待用户点击再开始练习。
